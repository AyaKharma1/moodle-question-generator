# Moodle-Fragenbank (Secure AI Moodle Question Generator)

A question bank for instructors who already keep their questions in Moodle.
Import any number of **Moodle XML exports** (also from different subjects),
see every question sorted by **Fach → Kategorie** together with the file(s) it
came from, find **duplicates, contradictions, near-duplicates and broken
questions**, and export a clean selection back to Moodle as XML with its
categories. Optionally, new questions can be generated by AI from lecture
materials (PDF / TXT / DOCX) and reviewed before export.

The application is **standalone**: it does **not** connect to any live Moodle
server. It produces a `.xml` file that you import manually into Moodle. See
[`MOODLE_IMPORT_GUIDE.md`](MOODLE_IMPORT_GUIDE.md).

> Academic project for Hochschule Bochum. The default AI provider is an offline
> **mock**, so the whole app runs with no paid API key and no network.

---

## Workflow

```
Moodle: export question bank (XML)  →  Import (one or many files)
   →  Check (duplicates, contradictions, similar, broken)
   →  Select in the Fragenbank  →  Export (Moodle XML with categories)  →  Moodle import
```

What the question bank does:

- **Provenance:** every question records each file and Moodle category it was
  found in, and every XML file it was later exported to (page *Verlauf*).
- **No duplicates:** a question that appears in several files (even with the
  answers in a different order) is stored once. Exporting it twice is impossible.
- **Contradictions:** same question text, different correct answers in two files.
- **Similar questions:** different wording, almost the same content (word
  overlap ≥ 80 %), so a student cannot get the same question twice in one test.
- **Broken questions:** no correct answer, duplicate answer options, images
  referenced but missing from the file, empty text.
- **Category size check:** Moodle draws random questions per category; the
  overview shows how many identical questions two students get on average.
- **Faithful round-trip:** imported questions are exported exactly as Moodle
  wrote them (images, grading settings, and types such as essay or matching).
  They are edited in Moodle, not in this app.

Optional AI generator: `Upload → Generate → Review & Approve`. Nothing generated
is exported until an instructor **explicitly approves** it.

## AI pipeline (why it is built this way)

```
Document → Text extraction → AI → Structured JSON → Validation → Moodle XML
```

The AI never writes XML directly. It returns structured data that is parsed into
typed objects, validated (grounding + duplicates), and only then converted to
Moodle XML by a separate, model-independent exporter. This keeps the exporter
testable and makes a misbehaving model unable to produce anything the app
accepts. More in [`ARCHITECTURE.md`](ARCHITECTURE.md) and
[`LEARNING_GUIDE.md`](LEARNING_GUIDE.md).

## Quick start (Docker — recommended)

Requires Docker + Docker Compose.

```bash
cp .env.example .env          # optional; defaults work for local demo
docker compose up --build
```

Then open:

- Frontend: <http://localhost:8081>
- API docs (Swagger): <http://localhost:8000/docs>
- Health: <http://localhost:8000/health>

Register a user in the UI and import the three sample files
`samples/moodle_*.xml` on the *Importieren* page (two subjects; they contain a
duplicate, a contradiction, a similar question and broken questions on
purpose). For the optional AI generator, upload `samples/sample_lecture_de.txt`.

> If port 8081 or 8000 is busy on your machine, change the `ports:` mapping in
> `docker-compose.yml`.

### Optional demo seed

Create a demo instructor and load the sample lecture:

```bash
docker compose exec backend python -m scripts.seed
# Login: demo@hs-bochum.example / demo-password-123
```

## Running without Docker (local dev)

**macOS / Linux, one command** (needs Python 3.11–3.13 and Node.js 18+):

```bash
bash start_mac.command     # or double-click it in Finder
```

It creates the Python environment, installs everything, migrates the SQLite
database and starts backend and frontend on <http://localhost:5173>.

Manual steps:

### Backend

```bash
cd backend
python3.11 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# Use SQLite for a zero-setup local run (or point DATABASE_URL at Postgres):
export DATABASE_URL="sqlite:///./dev.db"
export SECRET_KEY="dev-secret"
export AI_PROVIDER="mock"
alembic upgrade head
uvicorn app.main:app --reload
```

### Frontend

```bash
cd frontend
npm install
npm run dev        # http://localhost:5173 (proxies /api to :8000)
```

## Configuration

All configuration is environment-based (see [`.env.example`](.env.example)).
Key variables:

| Variable        | Default                    | Meaning                                   |
|-----------------|----------------------------|-------------------------------------------|
| `SECRET_KEY`    | dev placeholder            | JWT signing key — **set a strong value**  |
| `AI_PROVIDER`   | `mock`                     | `mock` (offline) or `openai`              |
| `AI_API_KEY`    | empty                      | only for `openai`                         |
| `DATABASE_URL`  | Postgres (compose)         | SQLAlchemy URL                            |
| `MAX_UPLOAD_BYTES` | 10 MB                   | upload size limit                         |

> Do **not** send real university documents to an external AI provider without
> authorization. See [`SECURITY.md`](SECURITY.md).

## Status / honesty notes

- Well-formed XML that follows the documented format is **not** proof of Moodle
  compatibility. Verify with a manual import (guide included).
- Prompt injection is mitigated, **not** solved. The real safety net is
  structured-output validation plus mandatory human approval.
